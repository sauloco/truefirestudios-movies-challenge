## Commands

Requires Node.js 22.18+ (scripts in `scripts/` run TypeScript directly via `node`).

- `npm run dev` — dev server on http://localhost:3000
- `npm run lint` / `npm run typecheck` — ESLint (`@nuxt/eslint`) / `nuxt typecheck` (vue-tsc)
- `npm run test:e2e` — Vitest + Playwright via `@nuxt/test-utils`; boots a real Nuxt server and a real browser. First run needs `npx playwright-core install chromium`.
- Single test file: `npx vitest run tests/e2e/api-recommendations.spec.ts` (add `-t "name"` to filter by test name)
- `npm run evaluate` — leave-one-out hit@5 evaluation of the recommender; sweep alphas with `npm run evaluate -- 0.55 0.6 0.65`
- `npm run build-catalog` — regenerate `server/assets/catalog.json` from TMDB (needs `TMDB_READ_ACCESS_TOKEN` or `TMDB_API_KEY` in `.env`; not needed to run the app or tests)

There are no unit tests: all tests are browser/API end-to-end under `tests/e2e/`. They never hit TMDB (catalog is committed, poster requests are intercepted, the catalog script is tested against `tests/e2e/fixtures/tmdb.json`).

## Architecture

Nuxt 4 app (`app/` is the srcDir) with Vuetify, `@nuxtjs/i18n` and a server-side recommender.

**Data flow.** Two committed JSON assets in `server/assets/` feed the server:
- `movies.json` — the supplied MovieLens-style dataset (movie titles + per-user liked ids). Loaded lazily and cached by `server/utils/dataset.ts`. User histories must never be exposed through the API.
- `catalog.json` — TMDB metadata (poster path, blurhash, overview, genres), generated by `scripts/build-catalog.ts` (title+year matching; mismatches fixed via its `OVERRIDES` map). `server/utils/catalog.ts` joins it with the dataset.

**Recommender** (`server/utils/recommender.ts`): item-based collaborative filtering on binary likes. Popularity-damped similarity (`POPULARITY_ALPHA`, `MIN_CO_LIKES`), candidate score = summed similarity to the visitor's picks normalised to 0–1, deterministic tie-breaks (popularity then id), and a "popular" cold-start when there are no picks. Each result carries a `because` list. Changing the algorithm or alpha should be checked with `npm run evaluate`. `scripts/evaluate.ts` reuses the same module.

**API** (`server/api/`): `GET /api/movies`, `POST /api/recommendations` (unknown ids → 400, schema failure → 422; schemas in `server/utils/schemas.ts`). Types shared between server and client live in `shared/types/index.ts`.

**Client** (`app/`): the home page (`pages/index.vue`) is a full-viewport CSS-3D room; `AppShell.vue` drops the width-capped container for the `index` route (by base name, since `/es` and `/ja` also serve it). The viewer and their picks live in localStorage (`composables/useViewer.ts`, `useLikedMovies.ts`), not the URL. Components are thin presentation pieces around the composables.

**Theming / i18n.** The rusticit.com theme (light + dark) is defined once in `vuetify.config.ts`; Vuetify composable `useLayout` is prefixed to `useVLayout` in `nuxt.config.ts` to avoid colliding with Nuxt's. Color mode follows the system until the toggle is used, then is stored in a cookie and applied during setup for SSR (`composables/useColorMode.ts`). All user-facing strings go in `i18n/locales/en.json`. Fonts are self-hosted via `@nuxt/fonts` (fontsource provider).
